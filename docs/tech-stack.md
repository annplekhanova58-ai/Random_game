# Технологический стек — Случайная игра Steam

Продукт — локальная программа на одном компьютере. Она открывается ярлыком в собственном окне операционной системы, читает публичную витрину Steam и хранит историю показов и настройки только на этом компьютере. Учётной записи, входа и сервера продукта для пользовательских данных нет. Телефонная вёрстка и публичный сайт не входят в первую версию.

Микросервисный каркас этого репозитория для данного продукта отклонён. Нефункциональные требования прямо это запрещают: отдельное окно, ярлык рабочего стола, один человек, отсутствие логина, локальные данные, чтение только публичного каталога Steam. Поэтому в рекомендуемый стек не входят PostgreSQL, JWT, API-шлюз, Docker Compose, брокер сообщений и сервер продукта. Шаблоны шлюза и сервисных API в `templates/docs/` к этой программе не применяются.

От каркаса сохраняется только знакомый слой интерфейса: React, Vite, TypeScript и Tailwind. Он работает внутри окна рабочего стола, а не как сайт.

## Recommended (Default)

**Tauri 2 + React + Vite + TypeScript + Tailwind.** Локальная история — файл SQLite через SQL-плагин Tauri. Каталог Steam — публичные HTTP-запросы store search и appdetails из самого приложения.

Этот вариант совпадает с утверждёнными требованиями: собственное окно, запуск ярлыком, данные только на компьютере, без аккаунта и без JWT. Rust остаётся тонкой оболочкой окна, файлов и HTTP. Правила розыгрыша, экраны и тексты живут на TypeScript.

| Слой | Выбор |
|------|--------|
| UI | React + Vite + TypeScript + Tailwind. Три экрана окна: `/`, `/result`, `/history`. Строки интерфейса — два словаря, `ru` и `en`. Отдельная телефонная вёрстка не делается |
| shell/window | Tauri 2. Собственное окно ОС, не вкладка браузера. Ссылка на игру открывается в браузере системы, окно программы остаётся открытым |
| local storage | Один файл SQLite в каталоге данных приложения через официальный SQL-плагин Tauri 2 (`sqlite`). В нём записи розыгрышей и одна запись настроек (граница цены USD и язык). Отдельный сервер базы не запускается. Один JSON-файл в том же каталоге допустим как упрощение внутри того же окна, но SQLite лучше держит уникальность `steam_app_id` и удаление записей |
| Steam access | Публичные HTTP store search и appdetails из оболочки приложения, без ключа пользователя и без входа в Steam. На время розыгрыша программа собирает подходящие игры в памяти, вычитает локальную историю и выбирает одну с равной вероятностью. Весь каталог на диск не пишется. Библиотека Steam не читается |
| tests | Vitest + Testing Library для интерфейса (граница цены, запятая и точка, язык, пустая выборка, ошибка витрины). Правила розыгрыша — чистая функция на TypeScript и небольшой тест Vitest. Отдельный тест на Rust нужен только если правило перенесут в оболочку |
| how the desktop shortcut is created | Установщик, который собирает Tauri (на Windows — установщик поставки), создаёт ярлык на рабочем столе. Ярлык открывает окно сразу на `/`. Если поставка идёт готовым исполняемым файлом без установщика, ярлык рабочего стола указывает на этот файл и это записано в инструкции к поставке |

Практические следствия, которые не меняют стек:

- Запрос к витрине идёт с витринной страной USD, чтобы цена была в долларах. Позиция без цены в USD в выборку не попадает. Курс приложение не считает.
- Равномерный выбор возможен только среди игр, прочитанных на этот розыгрыш. При высокой границе цены чтение страниц витрины занимает заметное время. Это сетевой шаг одного розыгрыша, а не повод поднимать сервер или хранить копию каталога.
- История, язык и граница цены работают без сети. Новый розыгрыш без витрины Steam не завершается.
- Playwright и контрактные тесты HTTP-шлюза первой версии не нужны: публичного сайта и собственного API нет.

## Alternative A

**Electron + React + Vite + TypeScript + Tailwind + better-sqlite3.** Поведение то же: своё окно, ярлык, локальная история, публичная витрина Steam, русский и английский. Тяжелее среда выполнения: в поставку входит Chromium.

| Слой | Выбор |
|------|--------|
| UI | Тот же React + Vite + TypeScript + Tailwind и те же три экрана, словари `ru` и `en` |
| shell/window | Electron. Главный процесс держит окно и файлы. Ссылка на игру открывается через браузер системы |
| local storage | Файл SQLite рядом с данными приложения через better-sqlite3 в главном процессе. Сервер PostgreSQL не используется |
| Steam access | Те же публичные store search и appdetails, вызов из главного процесса, без входа в Steam и без чтения библиотеки |
| tests | Vitest + Testing Library для интерфейса. Правила розыгрыша — тест Vitest на чистой функции TypeScript. supertest не нужен: HTTP-сервера продукта нет |
| how the desktop shortcut is created | Установщик Electron (electron-builder, NSIS на Windows) создаёт ярлык рабочего стола на исполняемый файл. Ярлык открывает окно на `/` |

Имеет смысл, если команда уже поставляет Electron и не хочет ставить Rust. Для одного человека на одном компьютере выигрыша в возможностях нет: окно, файл SQLite и те же запросы к Steam. Плата — размер поставки, расход памяти и нативный модуль better-sqlite3 при сборке.

## Alternative B

**Локальное веб-окно: React + Vite в браузере на localhost и маленький процесс Node.** История — локальный JSON-файл, который отдаёт этот процесс. Тот же интерфейс можно собрать быстро, но это хуже по двум утверждённым требованиям: «своё окно» и «ярлык рабочего стола». Вариант не рекомендуется.

| Слой | Выбор |
|------|--------|
| UI | React + Vite + TypeScript + Tailwind в обычном браузере по адресу localhost |
| shell/window | Вкладка или окно браузера, не окно программы. Закрытие вкладки и адресная строка остаются поведением браузера |
| local storage | JSON-файл на этом компьютере. Его читает и пишет маленький процесс Node. Отдельной базы и учётной записи нет |
| Steam access | Браузер с localhost не может напрямую читать витрину Steam из-за CORS. Процесс Node должен проксировать публичные store search и appdetails. Входа в Steam по-прежнему нет, но появляется лишний локальный сервер |
| tests | Vitest + Testing Library для интерфейса и Vitest для правил розыгрыша. Это самый близкий к обычному веб-проекту набор и при этом не закрывает требование отдельного окна |
| how the desktop shortcut is created | Ярлык может запустить процесс Node и открыть браузер на localhost. Это ярлык на сайт на этом же компьютере, а не на собственное окно программы. Такое не считается выполнением требования ярлыка |

Экранную часть здесь сделать быстрее всего. Для поставки владельцу компьютера вариант слабее рекомендуемого: два процесса, зависимость от браузера, обход CORS и ярлык, который не открывает окно приложения.

## Trade-offs

Масштаб продукта один: один человек и один компьютер, без синхронизации и без нескольких одновременных пользователей. В столбце масштабируемости сравнивается пригодность к этому пределу, а не способность вырасти в многопользовательский сервис. Такой рост требования первой версии запрещают.

| Вариант | Сложность (complexity) | Время до MVP (time-to-MVP) | Масштабируемость (scalability) | Знакомство команды (team familiarity) |
|---------|------------------------|----------------------------|--------------------------------|----------------------------------------|
| Recommended: Tauri 2 + React + SQLite | Средняя. Новый слой — оболочка Tauri и сборка Rust. Нет сервера, шлюза, JWT и отдельной СУБД | Среднее. Экраны на привычном React. Сверх этого — каркас Tauri, файл SQLite и установщик с ярлыком | Достаточная и совпадает с NFR. Окно и файл на одном компьютере. Горизонтальное масштабирование не закладывается | Интерфейс знакомый. Rust нужен для оболочки и установщика, не для правил розыгрыша |
| Alternative A: Electron + React + better-sqlite3 | Средняя. Весь продукт на JavaScript/TypeScript, но runtime тяжелее и сборка тянет нативный модуль SQLite | Чуть короче, если Electron уже знакомый. Поведение и экраны те же, что у рекомендуемого варианта | Та же граница: один компьютер. Память и размер установки больше, на функцию это не влияет | Выше для команды на Node и React. Rust не нужен |
| Alternative B: localhost + Node + JSON | Ниже как код экранов и выше как обходные пути: локальный процесс, прокси к Steam, файл JSON, ярлык на браузер | Самое короткое до первых экранов и не закрывает окно и ярлык без дополнительной оболочки | Та же один компьютер, плюс лишний процесс. Для утверждённого масштаба это не преимущество | Максимальное: браузер, React и Node. Знакомство не компенсирует промах по окну и ярлыку |

Рекомендуемый вариант берётся по умолчанию, потому что он выполняет окно, ярлык и локальное хранение без сервера продукта. Alternative A — запасной путь при отказе от Rust, с тем же поведением и более тяжёлой поставкой. Alternative B не рекомендуется.
